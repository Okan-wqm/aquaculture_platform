# C3 — Tailwind 3.4 → 4 migration (CSS-first `@theme` SSoT)

**Date:** 2026-06-16 · **Agent:** frontend-expert · **Cycle:** 2026-06-16-c3-tailwind4
**Plan:** Platform Modernization Program — Track C (Frontend), final wave C3.

## FE-MEDIUM-055 — Tailwind 3.4 is a major generation behind; migrate the federated frontend to Tailwind 4

**State:** OPEN → RESOLVED (build-green) by this PR.

### Finding
The whole federated web frontend (shell + 7 remotes + shared-ui design system) runs
on Tailwind CSS 3.4 — a full major behind 4.x. v4 is a ground-up rewrite (Rust/
Lightning-CSS engine, CSS-first `@theme` config, automatic content detection). The
6-agent 2026-06-11 tech scan listed "Tailwind 3 a major generation behind" as a
verified modernization finding; this resolves it for the federation modules.

### Resolution (build-green; aquamobil deliberately excluded)
Architectural, root-cause migration:

1. **Single CSS-first SSoT** `web/shared-ui/src/styles/theme.css` — every token from
   the deleted `web/shared-ui/tailwind.config.js` (171 lines) translated to v4
   `@theme`, **pinned to the exact v3 values** (colors incl. the WCAG-AA gray-400
   override, fonts, type scale with line-heights, radius, the full shadow scale,
   animations + keyframes) so the migration is **appearance-preserving**. Exported
   via `@aquaculture/shared-ui` `exports['./theme.css']`. Imported by every entry by
   relative source path (`../../../shared-ui/src/styles/theme.css`) — a package-name
   `@import` is intercepted by the modules' `@aquaculture/shared-ui → dist` vite alias
   and would resolve to a non-existent `dist/theme.css`.
2. **8 CSS entries** `@tailwind base/components/utilities` → `@import 'tailwindcss'` +
   theme import + `@source` (v4 no longer auto-scans external packages, so shell
   `@source`s every remote + shared-ui; each remote `@source`s shared-ui). Each adds a
   compat base layer restoring v3's `border-color: gray-200` default (v4 defaults to
   `currentColor`).
3. **tenant-admin** keeps its own dark-green/dark palettes as a local `@theme` and
   migrates its `backgroundImage` gradients to `@utility`; `.tenant-stat-card`'s
   `@apply tenant-card` is inlined (v4 forbids `@apply` of a non-utility class).
4. **PostCSS → `@tailwindcss/postcss`** (9 configs; replaces `tailwindcss` +
   `autoprefixer`, which v4 includes). Lower-risk than `@tailwindcss/vite` inside the
   federation vite configs; the vite plugin is a later perf optimization.
5. `tailwindcss` `^3.4.0 → 4.3.1` across 9 manifests; deleted 8 `tailwind.config.js`.

### Verification
- `vite build` green for all 7 federated entries + shared-ui: dashboard (984 modules),
  shell, tenant-admin, sensor-module (3194), farm-module (4230), hr-module (1924),
  admin-panel (1816) — each emits its compiled CSS.
- `invariants:fast` 77 suites / 1163 tests green.

### NOT verified here (tracked) — VISUAL regression gate
Tailwind 4's breaking changes are **visual** (shadow-scale rename, ring width,
`outline-none`→`outline-hidden`, border default). `vite build` confirms the CSS
**compiles** but cannot catch visual diffs. The plan's S7 gate is a **Playwright
screenshot diff**, which must run on CI / be reviewed manually before merge. The
token-pinning + the border compat layer are designed to preserve appearance, but
sign-off requires the screenshot gate.

### Excluded (documented exception)
`web/apps/aquamobil` stays on **Tailwind 3** — its Konsta 3 UI kit ships a Tailwind-3
preset; it is a standalone PWA (not a federation remote) with no shared CSS pipeline.
`hydroponics-module` has no tailwind config/CSS entry (renders via the shell) — dep
bumped only.

## Post-audit hardening (2026-06-16) — markup-codemod gaps the CSS-first migration missed

A read-only adversarial audit (frontend-expert + supply-chain + accessibility lenses)
caught that a **CSS-first** migration silently skipped the v4 **markup** codemod — the
class-renames `@tailwindcss/upgrade` would have applied to `.tsx`/`.ts`/`.css` source.
These render as build-green but visually/functionally broken, because v4 silently drops
unknown utilities from markup (only an `@apply` of a removed utility errors). All fixed
in this PR (verified in compiled CSS, not just build success):

1. **FE-HIGH (opacity utilities removed in v4)** — v4 deleted every `*-opacity-*`
   utility. **93 occurrences across 72 files** (`bg-black bg-opacity-50` modal/overlay
   backdrops, `ring-black ring-opacity-5` dropdowns, `border-opacity-50`) were
   un-rewritten, so backdrops rendered **solid opaque**. Rewritten to v4 slash syntax
   (`bg-black/50`, `ring-black/5`). The 2 *dynamic* cases (color from a runtime config
   object — `TodayTab` stat cards, `StatusWidget` border) had the alpha baked into the
   config token / made an explicit `border-gray-200/50`. **Coverage spans shell +
   every remote + `shared-ui` + `libs/`** (the design system + shared libs were the
   easiest surface to miss). Verified: `admin-panel` compiled CSS now emits
   `.bg-black\/50`, `.bg-gray-900\/50`, `.bg-white\/80` … and **zero** dead
   `.bg-opacity-*` rules.
2. **A11Y-HIGH (`outline-none` semantics flipped)** — in v4 `outline-none` now means
   `outline-style: none` (removes the outline); v3's transparent-outline focus behavior
   is v4's `outline-hidden`. **505 occurrences** (markup + `@apply`) rewritten
   `outline-none → outline-hidden` to preserve the exact v3 focus-visibility behavior.
3. **A11Y-MEDIUM / A11Y-LOW (`ring` default color + dynamic ring class)** — v4's default
   `ring` color is `currentColor` (v3 was `blue-500/50`). `Button` variants already pin
   an explicit `focus:ring-*`, so they are safe. The `Alert` dismiss button used a bare
   `ring-2` **and** an interpolated `ring-offset-${type}-50` (a runtime-built class
   Tailwind's static scanner never emitted — broken since v3). Fixed by adding a static
   `focusRing` field to the `typeStyles` map (complete literal class strings per type).
4. **FE-LOW (`theme()` string fn)** — `shell` `scrollbar-color: theme('colors.gray.300')`
   → `var(--color-gray-300)` (the v4 CSS-variable form; the `theme()` string syntax is
   deprecated).
5. **SUPPLY-MEDIUM (version-skew)** — `@tailwindcss/postcss` was a caret range
   (`^4.3.1`) while `tailwindcss` was pinned exact (`4.3.1`); pinned the plugin exact in
   all 9 manifests so engine + plugin move together (lockfile spec synced, no tree
   change).

**Verification:** `vite build` green for `shared-ui` + shell + all 7 remotes
(admin-panel, dashboard, farm-module, sensor-module, hr-module, tenant-admin,
hydroponics via shell); grep of compiled CSS confirms slash-opacity + `outline-hidden`
generate and no removed-utility rules remain.

### Still open (documented; tracked as orphan findings — NOT a C3 regression)
- **ORPHAN-MEDIUM-118** — v4 shifts the *default* palette (gray/red/green/blue…) from
  v3 sRGB-hex to oklch. Perceptually near-identical, not pixel-identical. Only the
  custom design-system tokens + the WCAG-AA `gray-400` override are pinned; the default
  scale is accepted as oklch. The plan-S7 Playwright screenshot gate is the authority on
  the residual color delta — **C3 must not merge on build-green alone.**
- **ORPHAN-LOW-119** — `hydroponics-module` standalone dev/preview is unstyled (no CSS
  entry); it only renders correctly as a shell remote. Carries `tailwindcss` +
  `@tailwindcss/postcss` devDeps nothing consumes. Pre-existing standalone gap.
- **ORPHAN-LOW-120** — `libs/farm-shared` + `libs/node-components` render Tailwind
  classes but were never in the v3 `content` globs and are not in the v4 `@source` set
  (faithful migration — same as v3). They render only because their classes
  (`bg-gray-*`, `text-*`) coincidentally overlap classes emitted elsewhere.
