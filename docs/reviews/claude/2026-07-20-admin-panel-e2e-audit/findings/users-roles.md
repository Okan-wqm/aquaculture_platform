### APA-049 [HIGH] Invite User flow can never succeed: FE sends non-whitelisted 'invitedBy' field, rejected by global ValidationPipe

- **Status:** CONFIRMED+DESIGNED (audited CRITICAL → verified HIGH)
- **Symptom:** The invite payload includes invitedBy: 'system' (web/modules/admin-panel/src/pages/UserManagementPage.tsx:275, services/api/users.ts:39-43) but InviteUserRequestDto has no invitedBy property (apps/admin-api-service/src/users/users.controller.ts:116-153; the controller instead takes the actor from req.user.id at line 391). The platform bootstrap registers a global ValidationPipe with whitelist:true + forbidNonWhitelisted:true (libs/backend-common/src/bootstrap/create-service-app.ts:458-460), so every invite request 400s with 'property invitedBy should not exist' before reaching the handler. Every 'Send Invite' attempt from the modal fails; the role-enum drift (next finding) would independently 400 the default role even if invitedBy were removed.
- **Evidence:**
  - `web/modules/admin-panel/src/pages/UserManagementPage.tsx:268-276`
  - `web/modules/admin-panel/src/services/api/users.ts:39-43`
  - `apps/admin-api-service/src/users/users.controller.ts:116-153`
  - `libs/backend-common/src/bootstrap/create-service-app.ts:458-460`
- **Verification:** Prior adversarial verdict accepted (isReal=true, HIGH, high confidence); re-read of all cited files today confirms every link unchanged: UserManagementPage.tsx:275 unconditionally sends invitedBy:'system'; the FE type makes it REQUIRED (services/types/users.ts:56 `invitedBy: string`); InviteUserRequestDto (users.controller.ts:116-153) has no such property and the handler takes the actor from req.user.id (:391); platform bootstrap registers whitelist:true + forbidNonWhitelisted:true globally (create-service-app.ts:458-461, useGlobalPipes :497), so every invite POST 400s with 'property invitedBy should not exist' before reaching the handler. This is an instance of the systemic FE-type-drift / DTO-whitelist-rejection class: admin-panel wire types are hand-written duplicates with zero compile- or test-time link to the BE DTOs. The repo itself already diagnosed this class once (libs/shared-contracts header, MSG-MEDIUM-057: 'two hand-maintained lists cannot be kept in sync by discipline alone') — the fix must reuse that proven cross-stack contract-lib pattern, not add a third hand copy.
- **Root cause:** The FE→BE link broke at the HTTP request contract, and it drifted because the FE type was authored against the wrong layer. The hand-written FE `InviteUserDto` (web/modules/admin-panel/src/services/types/users.ts:47-57) mirrors the backend SERVICE-layer params interface `InviteUserParams` (apps/admin-api-service/src/users/services/user-provisioning.service.ts:39-48, which requires `invitedBy: string` because the service needs an actor) — not the wire DTO `InviteUserRequestDto` (users.controller.ts:116-153), which deliberately omits `invitedBy` because actor identity is a server-side trust decision injected from the authenticated JWT (`req.user.id`, :391); accepting a client-asserted actor would be spoofable. The page's hardcoded `invitedBy: 'system' // In real app, get from auth context` is the smoking gun that the FE shape was copied from the internal params, never validated against the wire. Because the two type worlds are duplicated by hand with no compile-time or test-time link, the platform-global ValidationPipe (whitelist:true + forbidNonWhitelisted:true, libs/backend-common/src/bootstrap/create-service-app.ts:458-461) converts the silent drift into a deterministic 400 on every 'Send Invite'. Note the pipe is doing its job — the security posture is correct; the missing piece is a shared wire contract that makes such drift impossible to compile.
- **Fix design:** SYSTEMIC (pattern level, Tier 1 + Tier 3) — stand up `libs/admin-contracts` (`@aquaculture/admin-contracts`) as the SSoT for admin-panel↔admin-api wire shapes, cloned from the proven `libs/shared-contracts` isolation pattern (zero-dependency, no cross-lib tsconfig paths, path-aliased — NOT npm-installed — into the Vite bundle exactly as `web/apps/aquamobil` already aliases shared-contracts). shared-contracts itself is kept deliberately narrow by its no-enum-drift guard, so admin wire contracts get their own sibling lib rather than widening it. First module `src/users/invite-user.contract.ts` exports: (1) `INVITABLE_ROLES = ['TENANT_ADMIN','MANAGER','OPERATOR','VIEWER'] as const` + derived `InvitableRole` union (this same tuple is the plug-point for the sibling role-enum-drift finding: BE @IsEnum, FE select options, and FE default all derive from it); (2) `interface InviteUserRequest { tenantId: string; email: string; firstName?: string; lastName?: string; role: InvitableRole; moduleIds?: string[]; primaryModuleId?: string; message?: string }` — no invitedBy, by design; (3) `INVITE_USER_REQUEST_KEYS` const tuple with a compile-time exhaustiveness assertion (`Exclude<keyof InviteUserRequest, typeof INVITE_USER_REQUEST_KEYS[number]>` must be never, and `satisfies readonly (keyof InviteUserRequest)[]`) so the runtime key list cannot drift from the type; (4) `interface InviteUserResponse { success: true; userId: string; invitationId: string; deliveryStatus: string; message: string }` matching the controller return at :399-405 (the current FE response type also under-declares deliveryStatus/message — closed for free). Register the alias in tsconfig.base.json; add `paths` + vite `resolve.alias` entries in web/modules/admin-panel (same mechanics as aquamobil). BE LOCAL APPLICATION — move `InviteUserRequestDto` out of the controller into the existing `apps/admin-api-service/src/users/dto/` directory (per Layer Rules) as `invite-user.dto.ts` declaring `class InviteUserRequestDto implements InviteUserRequest`, with `@IsEnum(INVITABLE_ROLES)` sourced from the contract. `implements` makes dropping/renaming any contract field a compile error; the actor stays server-derived from req.user.id (unchanged — it is correct). FE LOCAL APPLICATION — delete the hand-written `InviteUserDto` from services/types/users.ts and re-export `InviteUserRequest`/`InviteUserResponse` from `@aquaculture/admin-contracts` (barrel stays stable for existing importers); retype `usersApi.invite: (data: InviteUserRequest) => apiFetch<InviteUserResponse>(...)`; remove `invitedBy: 'system'` + its comment from UserManagementPage.tsx:275. TypeScript excess-property checking on the call-site object literal now makes re-adding `invitedBy` — or any future non-wire field — a build failure: the wrong request is impossible to compile (Tier 1). TIER-3 GATE — `implements` cannot catch one gap: a contract field declared on the DTO but missing a validator decorator would be silently STRIPPED by whitelist. New spec `apps/admin-api-service/src/users/__tests__/invite-user-contract.spec.ts` closes it: (a) assert class-validator `getMetadataStorage()` decorated-property set of InviteUserRequestDto equals INVITE_USER_REQUEST_KEYS exactly (both directions); (b) run a real ValidationPipe constructed with the platform defaults (whitelist:true, forbidNonWhitelisted:true) — a canonical contract payload passes; the historical FE payload with `invitedBy` is rejected with 'property invitedBy should not exist' (the outage encoded as a permanent regression test). Subsequent findings of this drift class (role enums, tenant/settings endpoints) migrate endpoint-by-endpoint into admin-contracts instead of adding new hand copies. No defensive ?., no as any, no shims, no whitelist relaxation.
