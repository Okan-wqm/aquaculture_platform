## Context
Production compose files already use per-service PostgreSQL roles (commit `03e091da`), but the dev `docker-compose.yml` wired every service to the shared `aquaculture` superuser. The hardening report called this out as a mixed posture where production is stronger than dev. Dev should match the production isolation model — the init script already creates the per-service roles, the dev compose just had to consume them.

## Findings
**MEDIUM-003** (hardening-gap-report §Gap 5):
> Development compose also wires services to the shared `aquaculture` user rather than per-service credentials.

## Affected Files
- /var/aqua-saas/docker-compose.yml (every backend service now uses its per-service role)

## Atomic Commit Plan

```
refactor(dev): use per-service DB roles in dev compose

Production compose files migrated to per-service PostgreSQL roles in
03e091da. Dev compose still wired everything to the shared aquaculture
superuser, so the role model was only half-enforced. Dev now matches
production: each service connects as its dedicated role, with
<SERVICE>_SERVICE_DB_PASS (already generated by the init script)
sourcing the password. The legacy DB_PASSWORD env var is retained only
for the postgres container bootstrap (POSTGRES_PASSWORD, superuser).

Service → role mapping (matches init-scripts/00-init-schemas.sh):
  gateway-api        → gateway_service
  auth-service       → auth_service
  farm-service       → farm_service
  sensor-service     → sensor_service
  alert-engine       → alert_service
  billing-service    → billing_service
  hr-service         → hr_service
  hydroponics-svc    → hydroponics_service
  notification-svc   → notification_service
  messaging-service  → messaging_service
  admin-api-service  → admin_service

Side effect: gateway-api and auth-service JWT config updated to mount
the RS256 keypair (/var/run/jwt/{private,public}.pem) matching
docker-compose.prod.yml from P01. auth-service dev retains
ALLOW_DEV_JWT_SECRET + DEV_JWT_SECRET as an explicit escape hatch for
local work without key generation.

Closes: docs/security/2026-04-12-hardening-gap-report.md#MEDIUM-003
```
