## Context
Six messaging findings cover AI/embedding-related issues: index placement, AI message attribution, partial batch rollback, and token budget management. All touch the messaging AI subsystem within `apps/messaging-service/src/ai/`. Grouped by functional domain locality.

## Findings

**MSG-MEDIUM-012 — HNSW index created at parent migration level**
The HNSW vector similarity index for embeddings is created in a parent-level migration that runs on the public schema. In a schema-per-tenant deployment, each tenant schema needs its own HNSW index. Move index creation to the per-tenant migration path.

**MSG-MEDIUM-013 — GIN index for full-text search at parent migration level**
Same issue as MSG-MEDIUM-012 but for the GIN index on message content. Move to per-tenant migration.

**MSG-MEDIUM-038 — AI-generated messages lack isAiGenerated flag**
Messages generated by AI chat bridge do not set an `isAiGenerated: true` flag on the message entity. Users cannot distinguish AI-generated content from human messages. Compliance and transparency requirements demand this attribution.

**MSG-MEDIUM-041 — Embedding service has partial batch rollback**
When batch embedding fails mid-way (e.g., 50/100 messages embedded), the service rolls back the entire batch including successfully embedded messages. Use a per-item error tracking approach: mark failed items for retry, commit successful embeddings.

**MSG-MEDIUM-049 — Token budget race condition**
The AI chat bridge checks remaining token budget, then makes the LLM call, then deducts. Two concurrent requests can both pass the budget check and exceed the limit. Use atomic decrement (Redis DECRBY) before the LLM call, refund on failure.

**MSG-MEDIUM-050 — No cost-per-tool tracking for AI features**
AI tool invocations (summarize, translate, analyze) have no per-tool cost attribution. The billing service cannot charge tenants accurately for AI usage. Add a `tool_name` dimension to the token metering events.
