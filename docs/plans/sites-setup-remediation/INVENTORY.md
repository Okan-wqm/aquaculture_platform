## Runtime Baseline Signals

These signals are required before any compatibility or removal gate can pass:

- `setup_legacy_write_total{surface, operation, tenant}` for legacy mutation paths.
- `setup_legacy_read_total{surface, operation, tenant}` for compatibility reads.
- `setup_document_contract_total{operation, contract, ownerType, tenant}` where `contract` is `path` or `documentId`.
- `setup_frontend_legacy_operation_total{operationName, source, tenant}` for raw GraphQL and unsafe setup DTO casts.
- `setup_schema_sync_invocation_total{caller, tenant, reason}` for schema repair/provisioning calls.
- `setup_outbox_enqueue_total{aggregateType, eventType, tenant}` and outbox lag by setup event type.
- `setup_realtime_delivery_total{eventType, tenant}` and `setup_realtime_invalidation_total{queryKeyPrefix, tenant}`.
- Per-tenant rowcount snapshots for legacy rows, canonical rows, mapping rows, skipped rows, and conflict rows.
- Durable conflict counts for duplicate worker email/employeeNumber, duplicate farm/site and pond/tank identity, invalid URLs, duplicate document paths, orphan `pondId`, multiple primary contacts, supplier-site conflicts, and unmappable references.

## Current Baseline Blockers

- `farm_documents` was DROPPED (ORPHAN-HIGH-369 / FARMPLAT-HIGH-001): it was a built-but-unwired surface (no write API, no resolver/controller, no frontend), so the owner decision retired it rather than adopting it as the canonical document authority. The drop (`1805300000000-DropFarmDocuments.ts`) is pinned complete by `tests/invariants/sites-setup-remediation-plan-contract.spec.ts`. The legacy chemical/feed JSONB document metadata + path-based presign/delete therefore have no canonical successor here and await a separate owner re-decision (owner: farm-expert; tracked under ORPHAN-HIGH-369 follow-up).
- Site create/update/delete, site contact replacement, department create/update/delete, system create/update/delete, non-tank equipment create/update/delete, sub-equipment create/update/delete, tank-like equipment compatibility, supplier approved-site replacement, feeder calibration replacement, and tank create/update/status/delete now use the canonical tenant transaction/audit/outbox path; restore, chemical, feed, worker, Sentinel, and document writes still need the same treatment.
- No dry-run/execute backfill CLI or durable conflict ledger exists for worker-to-HR, farm-to-site, pond-to-tank, or document migration.
- Gateway upload still exposes upload-first/client-metadata-second flows and path-based presign/delete.
- Gateway realtime bridge now subscribes migrated setup events for site, department, system, equipment, sub-equipment, tank, supplier approved sites, site contacts, and feeder calibration; canonical document, chemical, feed, worker compatibility, and Sentinel events remain follow-up surfaces.
- Runtime tenant DDL repair is fail-closed by default in `SchemaManagerService.syncTenantSchema()`, and the admin schema sync service is report-only for existing tenants; remaining Phase 2 work is migration/tenant-ledger proof across bootstrap, clone, and schema invariant gates.
- Farm-module setup has raw operation strings, local DTO interfaces, unsafe casts, and browser alert/confirm paths.
- `farm-module` has no runnable project test files in the current Nx target, so frontend acceptance needs new focused tests before closure.
