# ISA-18.2 — Alarm Management Compliance

**Standard:** ANSI/ISA-18.2-2016 — *Management of Alarm Systems for the Process Industries*.

**Scope:** Alarm surface exposed by `suderra-agent` v1.6.0 — the alarm engine, alarm state machine, priority model, shelving semantics, audit-trail integration.

## Clause matrix (12 core clauses)

| # | Clause | Status | Evidence | Notes |
|---|--------|--------|----------|-------|
| 1 | Priority (§6.3) | PASS | `src/alarms.rs:27-53` — `AlarmPriority::{Diagnostic, Low, Medium, High, Critical}` enum with `Display` impl; priority carried through `AlarmEvent` (`src/alarms.rs:521-522`) | 5-level priority ladder matches ISA-18.2 §6.3 recommended practice of 3-5 priorities. |
| 2 | State machine (§5.2) | PASS | `src/alarms.rs:61-92` — `AlarmState::{Normal, Active, Acknowledged, Shelved, Suppressed, OutOfService}` with state-transition semantics at `src/alarms.rs:304-360` | Transitions: Normal→Active on entry condition, Active→Acknowledged on operator ack (`src/alarms.rs:387-416`), Active/Acknowledged→Normal on return-to-normal, Active/Acknowledged→Shelved on operator shelf (`src/alarms.rs:417-438`). |
| 3 | Deadband / hysteresis (§5.2.6) | PASS | `src/alarms.rs:145` (`dead_band` field on `AlarmDefinition`), chatter-preventing hysteresis applied before state transition | Prevents setpoint-edge chatter per ISA-18.2 §5.2.6. |
| 4 | Shelving (§5.2.7) | PASS | `src/alarms.rs:265-267` (shelf expiration time), `src/alarms.rs:417-438` (`shelve()` method with duration), `src/alarms.rs:488-506` (`AlarmEvent::Shelved { alarm_id, operator, expires_at, .. }`) | Operator-initiated finite-duration suppression with TTL per ISA-18.2 §5.2.7 — auto-unshelve on `expires_at` is enforced on every state-machine tick. |
| 5 | Suppression / Out-of-service (§5.2.8, §5.2.9) | PASS | `src/alarms.rs:72-73` — `AlarmState::Suppressed` (by design, e.g. maintenance) and `AlarmState::OutOfService` (equipment removed). ## KPI targets (owned by `operations-sla-writer`)

Once the FAIL rows above land (ROADMAP-Q3), the operator dashboard must expose the following KPIs with operator-approved thresholds:

| KPI | ISA-18.2 reference | Target (aquaculture deployment) |
|-----|--------------------|----------------------------------|
| Average alarm rate | §16.9 Table 13 | ≤ 6 alarms / hour / operator (ISA-18.2 "manageable" threshold) |
| Peak alarm rate | §16.9.1 (flood definition) | ≤ 10 alarms / 10-minute window |
| Annunciated alarm priority distribution | §16.9 | ~80 % Low, ~15 % Medium, ~5 % High, < 1 % Critical |
| MTTA (Mean Time To Acknowledge) | §16.9 | ≤ 60 s for Critical, ≤ 5 min for High, ≤ 30 min for Medium |
| % alarms acknowledged | §16.9 | ≥ 95 % within the priority's MTTA target |
| Standing alarms | §16.9.2 | Zero Critical for > 24 h; Medium accepted up to 7 d with justification |
| Chattering alarms | §16.9.3 | Zero alarms transitioning > 3 times / hour |

## Compliance posture

- **SL2 IEC 62443 FR6 impact:** FR6 "Timely Response to Events" is GATED by ISA-18.2 §16.9 KPI surface — auditors treat missing KPI metrics as a FR6 gap. The ROADMAP-Q3 delivery for clauses 7-11 also closes the last FR6 PARTIAL gap in [iec62443-4-2-gap.md](./iec62443-4-2-gap.md).
- **ISA-18.2 certification** — the standard is advisory, not a certification target; the documented target is "ISA-18.2 conformant operator-visible KPI surface" at 12-month horizon.
