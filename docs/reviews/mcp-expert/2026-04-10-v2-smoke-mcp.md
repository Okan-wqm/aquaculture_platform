## Findings

- `HIGH-001` Session, tenant, and cache scope are effectively process-scoped, not request-scoped. [server.ts#L111](/var/aqua-saas/mcp/farm-management/src/server.ts#L111), [server.ts#L123](/var/aqua-saas/mcp/farm-management/src/server.ts#L123), [server.ts#L128](/var/aqua-saas/mcp/farm-management/src/server.ts#L128), [server.ts#L156](/var/aqua-saas/mcp/farm-management/src/server.ts#L156), [client.ts#L147](/var/aqua-saas/mcp/farm-management/src/graphql/client.ts#L147), [client.ts#L151](/var/aqua-saas/mcp/farm-management/src/graphql/client.ts#L151), [client.ts#L302](/var/aqua-saas/mcp/farm-management/src/graphql/client.ts#L302). `createMcpServer()` derives one session once, bakes it into one `GraphQLClient`, and reuses that same client for all tool calls. Because cache keys are only `query::variables`, tenant/user isolation depends entirely on the unstated invariant “one process == one authenticated session.” That is only safe for strictly single-session launches; these files do not enforce that boundary.

- `HIGH-002` The trusted-gateway boundary is assumed, not enforced. [session-context.ts#L5](/var/aqua-saas/mcp/farm-management/src/auth/session-context.ts#L5), [session-context.ts#L17](/var/aqua-saas/mcp/farm-management/src/auth/session-context.ts#L17), [session-context.ts#L152](/var/aqua-saas/mcp/farm-management/src/auth/session-context.ts#L152), [session-context.ts#L171](/var/aqua-saas/mcp/farm-management/src/auth/session-context.ts#L171), [session-context.ts#L174](/var/aqua-saas/mcp/farm-management/src/auth/session-context.ts#L174), [session-context.ts#L211](/var/aqua-saas/mcp/farm-management/src/auth/session-context.ts#L211), [server.ts#L121](/var/aqua-saas/mcp/farm-management/src/server.ts#L121). `decodeJwt()` only decodes payload and checks `sub` and `tenantId`; there is no signature, issuer, audience, or `nbf` validation. That means identity and tenant scope are trusted purely because some upstream is expected to have authenticated first. If that deployment assumption slips, these files will forward forged identity and tenant headers.

- `HIGH-003` Refresh tokens are accepted as live session tokens. [session-context.ts#L63](/var/aqua-saas/mcp/farm-management/src/auth/session-context.ts#L63), [session-context.ts#L152](/var/aqua-saas/mcp/farm-management/src/auth/session-context.ts#L152), [session-context.ts#L224](/var/aqua-saas/mcp/farm-management/src/auth/session-context.ts#L224), [server.ts#L123](/var/aqua-saas/mcp/farm-management/src/server.ts#L123). The payload model distinguishes `access` and `refresh`, but session creation never rejects `refresh`. A refresh token in `MCP_JWT_TOKEN` becomes an outbound bearer credential and tenant source, which collapses token semantics at the gateway boundary.

- `HIGH-004` Partial GraphQL failures are silently converted into apparent success. [client.ts#L218](/var/aqua-saas/mcp/farm-management/src/graphql/client.ts#L218), [client.ts#L220](/var/aqua-saas/mcp/farm-management/src/graphql/client.ts#L220), [client.ts#L223](/var/aqua-saas/mcp/farm-management/src/graphql/client.ts#L223). When the gateway returns both `data` and `errors`, the client logs a warning and returns `data` anyway. In GraphQL, field-level auth denials and partial resolver failures commonly appear in that shape, so tools above this client can reason over incomplete or authorization-filtered data without any degraded-state signal.

- `HIGH-005` Graceful degradation exists only as late failure, not as clean capability scoping. [server.ts#L23](/var/aqua-saas/mcp/farm-management/src/server.ts#L23), [server.ts#L27](/var/aqua-saas/mcp/farm-management/src/server.ts#L27), [server.ts#L113](/var/aqua-saas/mcp/farm-management/src/server.ts#L113), [server.ts#L143](/var/aqua-saas/mcp/farm-management/src/server.ts#L143), [server.ts#L156](/var/aqua-saas/mcp/farm-management/src/server.ts#L156), [tools/index.ts#L148](/var/aqua-saas/mcp/farm-management/src/tools/index.ts#L148), [tools/index.ts#L181](/var/aqua-saas/mcp/farm-management/src/tools/index.ts#L181). The code claims “only math tools” are usable when JWT is missing or invalid, but the full tool set is still exposed and GraphQL-dependent tools fail only when called. The same problem will surface after token expiry or backend loss after startup: the process survives, but capability discovery remains misleading.

- `MEDIUM-006` Timeout discipline is present, retry discipline is undefined. [client.ts#L388](/var/aqua-saas/mcp/farm-management/src/graphql/client.ts#L388), [client.ts#L395](/var/aqua-saas/mcp/farm-management/src/graphql/client.ts#L395), [client.ts#L410](/var/aqua-saas/mcp/farm-management/src/graphql/client.ts#L410). Outbound calls have a single timeout, but there is no explicit bounded retry policy for safe idempotent reads and no explicit decision that “zero retries” is intentional. That leaves the tool layer in accidental single-shot mode for transient network or gateway failures.

- `LOW-007` The documented tool inventory is stale. [server.ts#L11](/var/aqua-saas/mcp/farm-management/src/server.ts#L11), [server.ts#L67](/var/aqua-saas/mcp/farm-management/src/server.ts#L67), [server.ts#L91](/var/aqua-saas/mcp/farm-management/src/server.ts#L91), [server.ts#L157](/var/aqua-saas/mcp/farm-management/src/server.ts#L157), [tools/index.ts#L123](/var/aqua-saas/mcp/farm-management/src/tools/index.ts#L123), [tools/index.ts#L141](/var/aqua-saas/mcp/farm-management/src/tools/index.ts#L141). `server.ts` still says 11 tools, while the registry now holds 13. This is not a direct safety break, but it weakens trust in the server’s own degraded-mode and capability documentation.

## Verdict

The code has some real safety structure already: startup survives missing/invalid JWT, backend calls have explicit timeouts, and the GraphQL client is instance-local. But it is not enterprise-safe as a generally reusable MCP boundary yet. The dominant weakness is that session scope, tenant isolation, cache safety, and trusted-gateway assumptions are encoded as deployment assumptions instead of enforced invariants. Under a strict single-session `stdio` deployment that may be tolerable; outside that narrow shape, this design is too fragile.
