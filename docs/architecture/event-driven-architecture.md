# Event-Driven Architecture

## Overview

The aquaculture platform uses NATS JetStream as its event bus for async communication between services. All events conform to the `BaseEvent` interface defined in `libs/event-contracts`.

## Event Publishing Standard

All publishers MUST use the **flat-object pattern**. See [ADR-006](../adr/006-event-contracts-flat-pattern.md) for the decision rationale.

```typescript
import { createBaseEvent } from '@platform/event-contracts';
import type { TenantCreatedEvent } from '@platform/event-contracts';

const event: TenantCreatedEvent = {
  ...createBaseEvent<TenantCreatedEvent>('TenantCreated', tenant.id),
  name: tenant.name,
  slug: tenant.slug,
};
await this.eventBus.publish(event);
```

## BaseEvent Contract

Every event MUST include these fields:

```typescript
interface BaseEvent {
  eventId: string;       // UUID v4, auto-generated by createBaseEvent()
  eventType: string;     // PascalCase, e.g. 'TenantCreated'
  timestamp: Date;       // auto-generated
  tenantId: string;      // MUST be top-level for NATS routing
  version: number;       // Schema version, start at 1
  correlationId?: string;
  causationId?: string;
  userId?: string;
  retryCount?: number;   // For dead-letter tracking
}
```

## NATS Subject Routing

```
platform.events.<eventType>
```

Tenant-scoped filtering is done by consumers using the top-level `tenantId` field.

## Dead-Letter Strategy

- `BaseEvent.retryCount` is incremented by the retry infrastructure on each re-delivery
- Consumers should check `retryCount` and route to `platform.dlq.<eventType>` when limit exceeded
- Compensation events (e.g. `SubscriptionProvisioningFailedEvent`) are defined in event-contracts

## Union Types

Each domain exports a union type for discriminated consumers:

```typescript
import type { AnyPlatformEvent, TenantEvent, FarmEvent } from '@platform/event-contracts';

function handleEvent(event: TenantEvent) {
  switch (event.eventType) {
    case 'TenantCreated': // narrowed to TenantCreatedEvent
    case 'TenantSuspended': // narrowed to TenantSuspendedEvent
  }
}
```

## Key Tenant Provisioning Flow (Events)

```
CreateTenantCommand
  → TenantCreatedEvent               (admin-api-service)
  → TenantModulesAssignedEvent       (admin-api-service)
  → TenantSubscriptionRequestedEvent (admin-api-service)
      → SubscriptionCreatedEvent              (billing-service)
      → SubscriptionProvisioningFailedEvent   (billing-service, on failure)
  → TenantProvisioningFailedEvent    (admin-api-service, on schema failure)
```

## Sensor Data Flow (Events)

```
MQTT/Modbus reading arrives
  → SensorReadingEvent              (sensor-service)
      → alert-engine evaluates rules
          → AlertTriggeredEvent     (alert-engine)
              → notification-service dispatches
                  → NotificationSentEvent / NotificationFailedEvent
```

## Edge Device I/O Data Flow (Real-time)

```
Edge Agent (scan cycle, 100-500ms)
  → MQTT publish: tenants/{tid}/devices/{code}/io_data
    → mqtt-listener.service.ts: handleEdgeIoData()
      → Validation (payload size ≤64KB, tags object, tag count ≤256)
      → Per-device throttle (1s minimum interval)
      → EventBus.publish('EdgeDeviceIoData')
        → WebSocket → EquipmentNodeOverlay
```

**EdgeDeviceIoData event format:**
```typescript
{
  eventId: string;        // UUID v4
  eventType: 'EdgeDeviceIoData';
  timestamp: Date;
  tenantId: string;
  deviceCode: string;
  tags: Record<string, { value: number | boolean; quality: string }>;
  version: 1;
}
```

**NOT:** Bu event NATS JetStream üzerinden değil, doğrudan EventBus → WebSocket
üzerinden iletilir. Yüksek frekanslı I/O verisi persist edilmez, sadece real-time
UI güncellemesi için kullanılır.
