# Mobile Messaging E2E Review — Consolidated Findings & Remediation Plan

**Cycle:** `2026-07-01-mobile-messaging-e2e`
**Surface:** AquaMobil PWA (`web/apps/aquamobil`) ↔ gateway-api (GraphQL federation + Socket.IO `/messaging`) ↔ messaging-service (CQRS + outbox) ↔ NATS/JetStream ↔ notification-service/FCM ↔ ai-service.
**Method:** 6 review waves, 15 read-only specialist agents + lead first-hand verification (grep/read, `file:line`) of every CRITICAL and every HIGH marked ✅ below. Wave reports: `2026-07-01-wave0-baseline.md`, `2026-07-01-sprint-a1-waves-1-3.md`, this file (Waves 4–6).

Fix commits carry `Closes: docs/reviews/mobile-messaging-e2e/2026-07-01-findings.md#{ID}`.

**Deployment decision: BLOCK.** The mobile messaging path is non-functional or unsafe on multiple independent axes (see the 4 CRITICALs). This is a review of the *current* state, not a regression from this branch — the branch adds only these review artifacts.

## Cross-agent conflict ruling (lead, first-hand)

**FCM background-push presentation (MSG-CRITICAL-056).** mobile-app-auditor found background pushes silently dropped by the in-memory `activeUserId` gate (reset to null on SW termination while the server now stamps `userId` on every push). tenant-isolation-auditor found the server always sends an FCM `notification:{title,body}` block (`push.service.ts:343`, lead-verified) which the FCM web SDK can auto-present **independent** of `onBackgroundMessage`, bypassing the gate → tenant-A sender name + badge shown on a shared device now in tenant B. These cannot both hold: either pushes show (gate bypassed → cross-tenant PII) or they drop (delivery dead). **Ruling: the empirical which-one is version/browser-dependent and does not need resolving, because the tier-1 remediation collapses both branches — send a data-only FCM message (drop the `notification` block) so the SW is the sole presenter and the userId gate is authoritative by construction, persist `activeUserId` in the FCM-SW's own IndexedDB so it survives termination, and implement the notificationRef deep-link in the FCM SW's `notificationclick`.** Registered as one CRITICAL cluster. The empirical test (does the current build present or drop) belongs in R1 verification, not as a gate on the fix.

## Cross-confirmed findings (two independent agents)

- **MSG-CRITICAL-058** (attachment MinIO objects never deleted) — found independently by W4 messaging-expert and W5 compliance-expert; merged under one ID.
- **Retention never runs** — W4 (`drop_chunks` on a non-hypertable, MSG-HIGH-073) and W5 tenant-isolation (retention cron enumerates policies from the empty source template) are **two independent root causes** for the same operator-visible truth: retention deletes nothing. Both must be fixed.

## Remediation plan — Sprints R1–R3

Every fix: architectural root-cause (tier 1–3), test-first, `nx affected --target=test && lint` green, commit trailer `Closes: …#{ID}`. Same-root-cause findings are fixed as one architectural change, not piecemeal.

### Sprint R1 — CRITICAL + live-path HIGH (gate to un-BLOCK)

1. **Messages cache-key SSoT** (MSG-CRITICAL-055 + blast radius): one co-located `messagesKey(tenantId,userId,channelId)` factory imported by every reader/writer; make `userId` a **required** parameter of `upsertMessageIntoChannelCache` + the socket setQueryData helpers (thread `user` into `useMessageSocket`); fix the two specs that pin the wrong key; add an invariant test asserting reader and every writer resolve to the same key. Reference architecture: `useFarmRealtimeSync` (invalidate-only, immune).
2. **FCM data-only cluster** (MSG-CRITICAL-056 + MSG-HIGH-069 + MSG-MEDIUM-069/MT-MEDIUM-051-push/MT-MEDIUM-052): data-only FCM messages, `activeUserId` in FCM-SW IndexedDB, notificationRef deep-link in FCM SW `notificationclick`, `data.badge` count. R1 verification includes the empirical present-vs-drop device test.
3. **Offline replay + refresh SSoT** (MSG-CRITICAL-057 + MSG-HIGH-058/059/060/061): one refresh lane (route the offline-sync freshness check through the single-flight coalescer; never call `refreshAuth()` directly), every enveloped input extends `MobileCommandEnvelopeInput` (or strip the envelope at `executeGraphQL` for non-enveloped mutations) enforced by an invariant, online-error→queue parity across send/edit/markRead, truthful queued/failed states in `ChatRoomPage`.
4. **Attachment erasure + retention** (MSG-CRITICAL-058 + MSG-HIGH-073 + MT-MEDIUM-054): enroll the object store in the erasure fan-out (per-service object-purge callback in the tenant-erasure executor; delete objects in anonymize/UserDeleted/retention), fix retention to use the correct partitioning primitive (row-DELETE fallback / declarative-partition DROP, not hypertable `drop_chunks`) AND enumerate tenant schemas per-iteration (mirror `KnowledgeExtractionService`).
5. **Live-stream convergence** (MSG-HIGH-063/064/065/066/067/068): ack'd `joinChannel` with degraded-state retry, server-cursor reconnect watermark (drop the client clock), `allMessagesSince` tie-break `>=` when `cursorId` present, retire-or-wire the unread HASH onto a single authority, membership-removal eviction handler, hydration recoverability (JetStream ack or client gap-detector).
6. **Edit legal-hold guard** (MSG-HIGH-062): inject `LegalHoldService`, check `isUnderLegalHold` before the content write, mirroring delete.

### Sprint R2 — remaining HIGH + push/media hardening

- **Media trust boundary** (MSG-HIGH-071/072/074/075): enforce actual object size (presign content-length range + HeadObject re-check against `MAX_FILE_SIZE`), pin the quota SUM per-tenant (`runInTenantTransaction`), stream/bound finalization off the send hot path, extend metadata stripping to video/Office/PDF (or reject at the allowlist).
- **Push pipeline** (MSG-HIGH-070 + NOTIF-HIGH-060): let fan-out errors reach JetStream NAK/DLQ (scope the catch to per-recipient), probe firebase-admin at init and flip `providerHealthy`.
- **Socket auth parity** (SEC-HIGH-053/054): inject the token blacklist into `validateToken`, arm a per-socket reAuth deadline that disconnects on no successful response.
- **Shared-socket ownership** (MSG-HIGH-052): hoist the socket to one ref-counted app-root provider; per-page hooks subscribe/unsubscribe, never connect/disconnect.
- **Compliance** (COMP-HIGH-060/061): add `exportMyMessages` to the audit map, extend legal-hold scope in the UserDeleted cascade to derived data + reactions/receipts.
- **AI pipeline** (MSG-HIGH-076 + MSG-HIGH-077 + MT-HIGH-051): **sequencing is load-bearing** — fix the tenant-pinning of the AI/analysis services (route through `runInTenantTransaction`, per-tenant enumeration for crons) BEFORE wiring the MessageSent→command dispatch and the ai-service NATS responder; wire the egress gate on `getMessageBatch` and the bridge context. If the AI channel feature is not shipping, delete the dead handlers/UI instead (remove the mute AI channel affordance from mobile).

### Sprint R3 — MEDIUM/LOW + test debt

- MEDIUM/LOW items above, registered as scheduled.
- **The structural gap: e2e for the real chat path.** Add e2e covering send→outbox→bridge→socket delivery, markRead→receipt, reconnect delta, and push dispatch (register token → SEND_PUSH → FCM shape) — none exists today (`e2e/tests/workflow/messaging.spec.ts` only exercises admin threads). Add runtime tests for the deployed SW handlers.
- Convert the two userless socket specs and add the cache-key invariant (from R1) into the permanent suite.
