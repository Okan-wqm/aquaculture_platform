# RS256-only JWT — eliminate the last HS256 surface (2026-06-13)

## SEC-HIGH-012 — auth-service retained an HS256 signing dev-fallback; RS256 is now enforced everywhere + permanently

**Severity:** HIGH · **Layer:** auth / cross-cutting · **Owner:** auth-security-expert
**Cycle:** 2026-06-10-round3 (operator directive: "RS256 tek olmalı, HS256 istemiyoruz" — ADR-016 / CRITICAL-001 completion)

### Observation
Verification was already RS256-only platform-wide (`getJwtVerifyOptions` /
`PlatformJwtModule`: `algorithms: ['RS256']`, HS256 rejected — CRITICAL-001 / WS2.B).
But two residues remained:
1. **auth-service signing dev-fallback** (`app.module.ts`): when RSA keys were absent +
   `ALLOW_DEV_JWT_SECRET=true`, it signed with `algorithm: 'HS256'` and `DEV_JWT_SECRET`.
   This was the **only live HS256 code** AND already dead — every consumer verifies
   RS256-only, so an HS256-signed token was rejected platform-wide. It was a pure
   algorithm-confusion surface.
2. **Stale comments** in 6 gateway/guard files falsely documented the current verify
   path as "enforces HS256" (the code uses `getJwtVerifyOptions` = RS256).

### Fix
- **auth-service is RS256-only in EVERY environment:** removed the HS256/DEV_JWT_SECRET
  fallback; the RSA keypair is now required everywhere (fail-fast with a
  `scripts/generate-jwt-keys.sh` hint if absent — consumers already require it).
- **Permanent guard:** new invariant `tests/invariants/jwt-rs256-only.spec.ts` (registered
  in invariants-fast) bans `algorithm: 'HS256'` signing config and `algorithms: ['HS256']`
  verify allowlists in all live code (comments stripped, so historical "BEFORE: HS256"
  notes documenting the fixed vuln do not trip it). 0 offenders.
- **Comment correctness:** the 6 false "enforces HS256" comments corrected to RS256.

### Verification
Invariant passes (0 HS256 in live code repo-wide). auth-service signing config is RS256
unconditionally. (GitHub CI runs the full auth-service build + the invariants-fast gate;
local-dev now requires an RSA keypair like every other service.)

### Tier
Tier-1 (make-it-impossible) + Tier-3 (make-it-detectable): the HS256 signing path is gone
AND the invariant prevents any HS256 algorithm config from re-entering the codebase.
