## ARIA-LOW-405 — residuals after the re-check

The re-check at `e71e67fb9` returned MERGE: every HIGH and MEDIUM item is fixed. The LOW residuals are
tracked as one finding (owner claude / okan, deadline 2026-10-23):

- **Unknown schemas pass unchecked.** `qualifiedTarget` refuses per-tenant tables of tenant-aware
  schemas only. It still accepts `public`, a `tenant_<uuid>` name matching `TENANT_SCHEMA_NAME_RE`,
  and any name the service catalog does not list. Fix: refuse the first two and require a
  catalog-listed schema.
- **Invariant blind spots.** `migration-column-index-pair` misses:
  - `ALTER t DROP COLUMN a, ADD COLUMN b`;
  - an unquoted `${col}` after `IF NOT EXISTS`, which is captured as `IF`;
  - DDL in private methods declared after `down()` and called from `up()`;
  - the plural `addColumns` / `createIndices` API;
  - variable (non-literal) table arguments.
- **`{ enumType }` is emitted unqualified.** The precondition (the enum type resolves on the
  migration's `search_path`, so it routes per tenant with the table) is not documented.
- **`concurrently` edge cases are undocumented.** A failed earlier build leaves an INVALID index that
  `CREATE INDEX CONCURRENTLY IF NOT EXISTS` skips silently. TimescaleDB hypertables reject
  `CONCURRENTLY`.
- **`MigrationColumnType` is `string`.** The vocabulary is enforced only at runtime. A
  template-literal union would reject a bad type at compile time.
- **DEBT OVERDUE is never written.** `docs/aria/CONTRACTS.md:1095-1097` moves an OPEN or IN_PROGRESS
  debt to OVERDUE once `current_date > due_date`. `aria_kernel/debt.py` declares the status, and
  `reflection.py` counts past-due OPEN/IN_PROGRESS rows as `overdue` when it reads them. No kernel path
  writes `current_status: OVERDUE`, so DEBT-2026-05-07-001 (due 2026-07-06) stays IN_PROGRESS on disk.
