# Research: Tenant Data Portability — GDPR Art. 20 Export, Import, Deletion Cascade

**Topic:** Bulk tenant export (JSON/NDJSON), tenant import for migration, deletion cascade with legal hold, proof-of-erasure

## Key Findings

1. **Article 20 scope.** The right to portability covers data "provided by" the data subject AND data generated by the subject's activity (click streams, sensor readings from their devices, measurements entered by them). It does NOT cover derived data (risk scores, ML predictions, inferred insights).
2. **Format requirements.** "Structured, commonly used, and machine-readable." Accepted formats: JSON (nested data), NDJSON (streaming bulk export — one record per line), CSV (flat tabular), XML. The EDPB prefers JSON for complex hierarchies and CSV for flat tables. Proprietary binary formats are NOT compliant.
3. **Two transmission modes.** Direct transmission of a bundle (signed URL to a ZIP/NDJSON), or an automated tool / API that allows the subject to extract data programmatically. For large tenants (> 1 GB export), the API / automated tool approach is preferred because a single bundle becomes operationally impractical.
4. **Signed URL expiry.** Industry standard: ≤ 7 days maximum, 24 hours default for sensitive exports. Bucket-level lifecycle deletes expired objects automatically. Single-use / consumed flag preferred.
5. **Export covers a tenant boundary, not a user boundary.** For a B2B SaaS, the "tenant" is the data controller in GDPR terminology; per-user export requests are handled by the tenant admin, not the platform SUPER_ADMIN. The platform is the data processor and provides the export tooling.
6. **NDJSON for bulk tenant export** is the practical choice for SaaS scale — each table becomes a separate NDJSON file within a ZIP, allowing stream parsing and partial recovery on interruption. JSON arrays break at gigabyte scale.
7. **Bulk tenant export must be async.** Submit export request → `202 Accepted + jobId` → worker streams tables into object storage → signed URL returned via email / webhook → TTL expiry.
8. **Tenant import / migration from another platform.** Reverse of export: subject presents NDJSON bundle → platform validates schema → runs per-table import in a saga → maps foreign IDs to new UUIDs → generates import report with per-record status.
9. **Deletion cascade across bounded contexts.** GDPR Art. 17 erasure must cascade across every service holding tenant data: farm-service, sensor-service, hr-service, billing-service, notification-service, messaging-service, ai-service. Each service exposes `eraseTenantData(tenantId)` handler. Incomplete cascade = GDPR non-compliance.
10. **Legal hold precedence.** Any tenant under `legal_hold = true` cannot be erased regardless of Art. 17 request. Legal hold overrides erasure and must be documented to the subject as a lawful basis for retention (Art. 17(3)(e)).
11. **Proof-of-erasure certificate.** After successful erasure: hash-signed audit event `TenantErased { tenantIdHash, erasedAt, operatorId, method, schemaDropped, servicesErased[], legalHoldHonored }`. Hashed tenantId is not PII and can be retained indefinitely for compliance evidence.
12. **Anonymization vs erasure.** True erasure removes the row. Anonymization (replacing PII with crypto-random values) is acceptable when relational integrity must be preserved (e.g., financial records). Predictable anonymization (`user_${id}`) defeats the purpose and is a CRITICAL finding.
13. **Response window.** 1 month per Art. 12, extendable to 3 months for complex requests with notification to the subject.

## Security Concerns

- **Signed URL leakage via server logs** — export URLs must NEVER be logged in plaintext.
- **Cross-tenant export via bundle swap** — export job writes to the wrong tenant's object-storage path if path derivation doesn't bind to the requesting tenant's UUID under a trusted JWT claim.
- **Import without schema validation** — allows attacker to inject arbitrary UUIDs / enum values into the tenant's data.
- **Import mapping leaks cross-tenant IDs** — foreign UUIDs in the import must be remapped, not preserved.
- **Incomplete cascade erasure** — a single service missed during erasure = GDPR non-compliance.
- **Derived data exported beyond Art. 20 scope** — exporting proprietary ML predictions leaks trade secrets AND overshoots the Art. 20 mandate.
- **Predictable anonymization values** (`user_${id}`, counter-based) defeat anonymization = CRITICAL.

## Performance Concerns

- **Single-file bundle > 1 GB** is operationally fragile — NDJSON + per-table splitting allows resume and stream parse.
- **Bulk export pressure on source DB** — must use a replica or an isolated read-only connection budget.
- **Import transaction size** — large imports must be chunked per table to avoid long-running transactions that hold schema locks.
- **Cascade erasure across 12 services** — parallel fan-out with per-service completion tracking; serial processing is acceptable at low scale but HIGH at platform maturity.

## Architectural Implications for multi-tenant-saas-expert reviews

- Tenant export must be async, NDJSON + ZIP, tenant-bound path derivation from JWT claim only.
- Tenant import must validate schema, remap foreign UUIDs, and run as a saga with per-table compensation.
- Cascade erasure must be fan-out across every bounded context with explicit completion tracking.
- Legal hold check precedes every erasure or purge call.
- Proof-of-erasure certificate is a hash-signed append-only audit event.
- Signed URLs expire ≤ 7 days, bucket lifecycle auto-deletes, URLs not logged.

## Domain Rule Additions for multi-tenant-saas-expert

- **Export format:** NDJSON + ZIP for bulk tenant export; JSON for small per-user exports. Proprietary/binary formats = HIGH (Art. 20 non-compliance).
- **Export scope:** subject-provided data + subject-generated activity data only. Derived data (ML scores, predictions) NOT exported unless separately consented = HIGH overshoot.
- **Export is async** (`202 Accepted + jobId`). Synchronous export on large tenants = HIGH.
- **Signed URL TTL ≤ 7 days**, 24 h default for sensitive exports. Longer = HIGH.
- **Signed URL never logged in plaintext.** Logged URL = CRITICAL.
- **Path derivation from JWT claim only.** Path from request body / header = CRITICAL (cross-tenant swap).
- **Import validates schema + remaps foreign UUIDs.** Missing validation = HIGH; preserving foreign UUIDs = CRITICAL.
- **Cascade erasure fan-out** across every service holding tenant data (farm, sensor, hr, billing, notification, messaging, ai). Missing any = CRITICAL.
- **Legal hold check precedes erasure.** Missing = CRITICAL.
- **Proof-of-erasure certificate** — hash-signed audit event `TenantErased` retained indefinitely (hashed tenantId is not PII). Missing = CRITICAL.
- **Anonymization uses crypto-random values** (`crypto.randomUUID()`, `crypto.randomBytes`). Predictable (`user_${id}`, counter) = CRITICAL.
- **Response window** — 1 month standard, 3 months for complex with notification. Missing SLA tracking = HIGH.
- **NDJSON per-table file split** when export > 100 MB. Single huge JSON array = MEDIUM (operational fragility).
