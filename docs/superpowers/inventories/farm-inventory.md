Volume is auto-computed from dimensions based on tank type (circular = pi*r^2*h, rectangular = l*w*h, etc.)\n2. Water volume is computed using waterDepth instead of tank depth\n3. Density = currentBiomass / (waterVolume || volume)\n4. Cannot exceed maxBiomass or maxDensity when adding biomass\n5. Status transitions are validated by `canTransitionTo()` state machine\n6. Department is required (onDelete: RESTRICT)\n\n### Batch Rules\n1. Batch numbers are auto-generated (B-2024-XXXXX)\n2. Status transitions validated by state machine\n3. Dual weight tracking: theoretical (FCR-based) vs actual (measured)\n4. FCR = totalFeedConsumed / weightGain\n5. SGR = ((ln(finalWeight) - ln(initialWeight)) / days) * 100\n6. Mortality rate = totalMortality / initialQuantity * 100\n7. Survival rate = ((initialQty - mortalityCount) / initialQty) * 100\n8. Retention rate = (currentQty / initialQty) * 100 (includes culls)\n9. Species is required (onDelete: RESTRICT)\n10. Cleaner fish batches have separate lifecycle tracking per production tank\n\n### Feeding Rules\n1. DailyFeedingExecution can only record feeding in PLANNED or IN_PROGRESS status\n2. FCR cannot be zero (DivisionByZeroError)\n3. fishCount cannot be zero (DivisionByZeroError)\n4. Growth calculation: feed / FCR = growth\n5. New biomass = old biomass + growth\n6. New avg weight = (new biomass / fish count) * 1000\n7. Feed transition warnings generated when fish weight approaches next feed range\n8. Skipping requires a reason\n9. JSONB validation on both calculations and actualResults structures\n\n### Growth Rules\n1. Statistics auto-calculated (mean, median, stdDev, CV, 95% CI using t-distribution)\n2. Condition factor K = 100 * W / L^3\n3. Performance evaluation: EXCELLENT (>10% over), GOOD (+/-5%), AVERAGE (+/-10%), BELOW_AVERAGE (-10-20%), POOR (>-20%)\n4. Grading suggested when CV > 25%\n5. Biomass estimated: averageWeight * populationSize / 1000\n6. Measurements can be verified by supervisor\n\n### Harvest Rules\n1. Quality approval required before shipment\n2. Yield = processedWeight / grossWeight * 100\n3. Size grading: XS (<200g), S (200-300g), M (300-400g), L (400-500g), XL (500-700g), XXL (>700g)\n4. Lot numbers auto-generated (LOT-2024-XXXXX)\n5. Status flow: IN_PROGRESS -> COMPLETED -> QUALITY_CHECK -> DISPATCHED -> DELIVERED\n\n### Chemical Rules\n1. Withdrawal period must be complete before harvest\n2. Stock status auto-updates: quantity <= 0 = OUT_OF_STOCK, quantity <= minStock = LOW_STOCK\n3. Expiry date tracking\n4. Some chemicals require approval (requiresApproval flag)\n\n### Equipment Rules\n1. Equipment can be hierarchical (parent/child)\n2. isTank flag distinguishes tank-type equipment\n3. Equipment can serve multiple systems (M2M via EquipmentSystem)\n4. Volume auto-computed for tank-type equipment from specifications\n\n### Species Rules\n1. Water quality checks against species-specific optimal conditions\n2. Temperature critical/warning/optimal ranges\n3. Growth stages define feeding rates and densities per weight range\n4. Harvest days calculated per input type (egg, larvae, fry, fingerling, etc.)\n\n---\n\n## PART 6: COMPLETE WORKFLOWS\n\n### Batch Lifecycle (end-to-end)\n```\n1. Create Species (reference data)\n2.
