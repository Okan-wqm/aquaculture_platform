# Domain Apps Review

**Date:** 2026-05-30  
**Scope:** `apps/farm-service`, `apps/sensor-service`, `apps/hydroponics-service`, `apps/alert-engine`, `apps/ai-service`  
**Mode:** Read-only architecture review synthesized from the domain agent.

## Purpose

Validate aquaculture domain apps for tenant-safe data-plane ownership, event reliability, subgraph hardening, fail-closed runtime defaults, and domain correctness under failure.

## Findings

### DOMAIN-CRITICAL-001: Sensor SSOT and tenant boundary are split

`sensor-service` is configured for tenant schemas/RLS, but ingestion metadata lookup is unqualified and not tenant-scoped, metrics insert into unqualified `sensor_metrics`, and baseline FK points to source-schema sensor metadata.

Evidence:

- `apps/sensor-service/src/app.module.ts:331`
- `apps/sensor-service/src/ingestion/sensor-meta-cache.service.ts:80`
- `apps/sensor-service/src/ingestion/batch-processor.service.ts:163`
- `apps/sensor-service/src/database/migrations/1800000000000-Baseline.ts:240`

Enterprise remediation:

- Decide one data-plane SSOT: central source-schema metadata/Timescale with explicit RLS, or per-tenant metadata plus a deliberate replicated ingestion read model.
- Align GraphQL CRUD, sidecar ingestion, metrics writes, cache keys, migrations, RLS, and query paths to that decision.
- Add tests covering tenant A/B sensors, sidecar ingestion, metadata cache invalidation, and Timescale insert/read behavior.

### DOMAIN-HIGH-001: Sensor legacy data plane can boot in production by default

`SENSOR_SERVICE_PROFILE` falls back to `legacy`, and `DataIngestionService` starts active MQTT sensors outside tenant request context.

Evidence:

- `apps/sensor-service/src/config/sensor-service-profile.service.ts:34`
- `apps/sensor-service/src/ingestion/data-ingestion.service.ts:73`
- `apps/sensor-service/src/ingestion/data-ingestion.service.ts:129`
- `docker-compose.prod.yml:322`

Enterprise remediation:

- Production profile must be explicit and fail closed.
- Legacy ingestion must not start in production unless an audited compatibility mode is enabled.
- Add deploy/env validation for sensor profile.

### DOMAIN-HIGH-002: Alert cooldown can suppress alerts before durable state exists

`alert-engine` sets Redis cooldown before saving durable history/incident state and swallows downstream failures.

Evidence:

- `apps/alert-engine/src/alert/services/alert-evaluation.service.ts:273`
- `apps/alert-engine/src/alert/services/alert-evaluation.service.ts:286`
- `apps/alert-engine/src/alert/services/alert-evaluation.service.ts:320`

Enterprise remediation:

- Cooldown must be recorded transactionally after durable alert state, or moved to a database idempotency/cooldown table.
- Failures must be retryable and observable, not hidden by Redis cooldown.
- Add tests for DB failure after cooldown attempt and concurrent alert evaluation.

### DOMAIN-HIGH-003: Critical farm/alert events are best-effort despite outbox intent

Farm task/storage paths save durable state and then directly publish events in catch-and-log blocks. Alert triggered/resolved/escalated events are direct publishes, while `alert_outbox` appears only as an RLS exclusion.

Evidence:

- `apps/farm-service/src/task/services/task.service.ts:149`
- `apps/farm-service/src/task/services/task.service.ts:155`
- `apps/farm-service/src/storage/handlers/record-stock-movement.handler.ts:240`
- `apps/alert-engine/src/alert/services/alert-evaluation.service.ts:435`
- `apps/alert-engine/src/app.module.ts:174`

Enterprise remediation:

- Domain-critical state changes must emit through transactional outbox or equivalent durable event storage.
- Consumers must be idempotent and replayable.
- Add a static check blocking save-then-best-effort publish in critical domains.

### DOMAIN-HIGH-004: GraphQL/control-plane throttling is inconsistent

Farm imports throttling and sensor uses sensitive throttling decorators, but the shared throttler guard is not registered globally in those apps. Alert has no throttler and only depth limiting.

Evidence:

- `libs/backend-common/src/security/throttler/throttler.module.ts:33`
- `apps/sensor-service/src/vfd/resolvers/vfd-command.resolver.ts:48`
- `apps/farm-service/src/water-quality/water-quality.resolver.ts:190`
- `apps/alert-engine/src/app.module.ts:123`

Enterprise remediation:

- Register throttler as an `APP_GUARD` where decorators imply enforcement.
- Add GraphQL query complexity limits for alert and other exposed subgraphs.
- Add mutation abuse tests for water quality and VFD command paths.

### DOMAIN-HIGH-005: AI subgraph lacks service identity and deterministic SDL artifact path

Other subgraphs use `ServiceIdentityGuard`; AI registers tenant, role, and throttler guards only. AI also uses `autoSchemaFile: { federation: 2 }` without deterministic generated SDL output.

Evidence:

- `apps/ai-service/src/app.module.ts:135`
- `apps/ai-service/src/app.module.ts:270`

Enterprise remediation:

- Add service identity first in the guard chain.
- Materialize AI SDL to the same deterministic subgraph artifact pattern as other services.
- Add composition/gateway tests that include AI.

### DOMAIN-MEDIUM-001: Hydroponics authorization relies on mutable JSON

Any `MODULE_USER` can update tenant config, while delete ownership checks `settings.createdBy`, which is user-controlled and not set server-side.

Evidence:

- `apps/hydroponics-service/src/setup/resolvers/setup.resolver.ts:95`
- `apps/hydroponics-service/src/setup/resolvers/setup.resolver.ts:113`
- `apps/hydroponics-service/src/setup/resolvers/setup.resolver.ts:166`
- `apps/hydroponics-service/src/setup/entities/hydroponics-config.entity.ts:10`

Enterprise remediation:

- Add immutable ownership columns or restrict mutations to manager/admin roles.
- Validate JSON settings against a schema and move ownership outside mutable JSON.
- Add self/non-owner/admin authorization tests.

### DOMAIN-MEDIUM-002: AI token budgets are checked, not reserved

AI checks budget before model calls and records usage after completion. Concurrent runs or crashes can overspend or under-record costs.

Evidence:

- `apps/ai-service/src/agent/agent-runner.service.ts:113`
- `apps/ai-service/src/agent/agent-runner.service.ts:240`
- `apps/ai-service/src/agent/agent-runner.service.ts:384`

Enterprise remediation:

- Implement atomic reservation and reconciliation with persisted usage events.
- Add concurrency and crash/retry tests.

### DOMAIN-MEDIUM-003: Farm reminder notifications can lose tenant context

The scheduler emits `tenantId`, but the listener sends `notification.send` with `tenantId: undefined`.

Evidence:

- `apps/farm-service/src/scheduler/feeding-scheduler.service.ts:833`
- `apps/farm-service/src/events/listeners/feeding-completed.listener.ts:80`

Enterprise remediation:

- Require tenant context in notification command contracts.
- Add contract tests for all farm-to-notification events.

## Recommended Fix Order

1. Decide and implement sensor SSOT/data-plane model.
2. Fix alert lifecycle reliability and cooldown durability.
3. Convert farm/alert critical events to outbox/idempotent consumers.
4. Apply subgraph security baseline: service identity, throttling, depth/complexity, SDL output.
5. Harden hydroponics ownership and JSON schema.
6. Implement AI token reservation/reconciliation.
7. Add architecture tests for tenant context, outbox usage, throttler registration, and SDL generation.
