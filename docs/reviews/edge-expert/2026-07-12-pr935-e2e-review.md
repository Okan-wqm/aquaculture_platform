## Verdict

The 17 remediation commits are architecturally sound in direction; the command-path security slice,
the Arc-bytecode change, and the SQLCipher factory verified clean. However the review found **5 HIGH
defects** — three of which undermine the exact guarantee their own commit claims — plus
process/registry gaps. All are fixable in-branch; fixes land as follow-up commits carrying `Closes:`
trailers against the finding IDs below.

## HIGH findings

### PR935-HIGH-001 — CI advisory-ignore removal is factually wrong; both supply-chain gates go red

`sens-api-gateway/deny.toml`, `sens-api-gateway/.cargo/audit.toml`,
`.github/workflows/sens-api-gateway-ci.yml`, `.github/workflows/edge-agent-release.yml` (commit
2856b241). The `RUSTSEC-2026-0173` ignore was removed on the claim that `proc-macro-error2` "no
longer resolves in the tree". It still resolves in the audited lockfile
(`sens-api-gateway/Cargo.lock` — `proc-macro-error2 2.0.1` via `defmt-macros 1.0.1`), and the
advisory is live upstream (`informational = "unmaintained"`, `patched = []`, not withdrawn —
verified against the RustSec DB on 2026-07-12). The claim holds only for the **root** workspace
lockfile, which these gates do not audit. `cargo audit --deny warnings` and cargo-deny
`[advisories] version = 2` both treat the matching unmaintained advisory as an error. **Fix:**
restore the ignore on all four sync-locked surfaces with the original owner/deadline metadata.

### PR935-HIGH-002 — Shutdown coordinator's timeout arm never aborts a wedged actuator write

`sens-api-gateway/src/shutdown.rs:108-119`. `tokio::time::timeout(t, handle)` consumes the
`JoinHandle`; the `Err(_)` arm logs _"aborting"_ but the task is **detached**, not cancelled. A
fieldbus write wedged past the per-task budget keeps running while the sequence proceeds to
`ApplyingSafeState`, and can overwrite the fail-safe value after it is applied — exactly the
EDGE-HIGH-015 hazard commit 4802430b claims to close. **Fix:** poll via `&mut handle` so the handle
survives the timeout, then `handle.abort()` and await the abort before proceeding.

### PR935-HIGH-003 — Shutdown watchdog can fire before safe-state and reports success

`sens-api-gateway/src/main.rs:5886-5897`. The hard deadline is `min(2×T+10, 80)` s while the
coordinator drains ~15 registered tasks **sequentially** at up to `T=30` s each (worst case 450 s).
Three wedged tasks starve the ceiling: the watchdog fires before `ApplyingSafeState` is reached,
leaves actuator outputs live, and calls `std::process::exit(0)` — monitoring sees a clean shutdown
and `Restart=on-failure` units do not restart. Additionally the watchdog timer runs on the same
2-worker runtime it guards; two non-yielding tasks starve the timer itself. **Fix:** budget the
drain deadline from the registered task count (or drain concurrently), run the watchdog on a
detached OS thread, apply an emergency safe-state before the forced exit, and exit non-zero.

### PR935-HIGH-004 — `edge_seq` uniqueness does not survive power loss; replays drop fresh alarms

`sens-api-gateway/src/offline_queue.rs` (`reserve_seq_block`) + WAL `synchronous=NORMAL`. The Hi/Lo
high-water-mark commit is not fsync-durable: in WAL mode with NORMAL, commits sync only at
checkpoint, so a power cut can rewind `edge_seq_state.reserved_hwm` and re-issue already-used
`(device_id, edge_seq)` pairs. The backend dedup that EDGE-CRITICAL-004 enables would then discard
legitimate fresh telemetry **and alarms**. The invariant test covers clean reopen only. **Fix:**
make the once-per-256-messages reservation commit durable (scoped `synchronous=FULL` toggle owned by
the SQLCipher factory), keeping the hot path untouched.

### PR935-HIGH-005 — `/lifecycle/confirm-active` remains anonymous unlike the observability GETs

`sens-api-gateway/src/lifecycle.rs` (auth skip when `auth_key` is `None`) vs
`sens-api-gateway/src/health.rs` (router). Commit 6927ff58 gates the three read-only GETs
fail-closed on non-loopback binds, but the state-mutating firmware A/B
`POST /lifecycle/confirm-active` on the same server still skips auth entirely when no key is
configured, with no bind-address check — on a `0.0.0.0` bind any network peer can anonymously
confirm a firmware slot. **Fix:** enforce the auth gate as router middleware with an explicit
`/health` + `/ready` anonymous allowlist, so every current and future route on this server is gated
by construction (see PR935-MEDIUM-008).

## MEDIUM findings

### PR935-MEDIUM-001 — LoRaWAN fcnt replay window survives power cuts

`sens-api-gateway/src/lora/session.rs` (`synchronous=NORMAL`). Same durability class as
PR935-HIGH-004: the atomic `check_and_advance_f_cnt_up` write-through closes the replay window
across process crashes only; a power cut can rewind the counter and reopen it. LoRa uplink rates are
radio-bounded, so per-advance durable sync is affordable. **Fix:** open the session store with
factory-owned `synchronous=FULL` durability.

### PR935-MEDIUM-002 — SQLCipher SSoT invariant has false-negative needle holes

`sens-api-gateway/tests/invariants/sqlcipher_factory_ssot.rs`. (a) raw-string SQL
(`r#"PRAGMA key = …"#`) carries no escaped quote and evades the needles; (b) the passphrase form
`PRAGMA key = '…'` matches nothing — a store could drift to KDF passphrase keying, the exact
EDGE-CRITICAL-002 class; (c) `pragma_update` spacing / `DatabaseName::Main` / `"rekey"` variants are
missed; (d) the test-seed marker exempts any line without verifying it is under `#[cfg(test)]`; (e)
durability pragmas (`journal_mode`/`synchronous`/`busy_timeout`/`auto_vacuum`) are claimed
factory-owned but their re-emission outside the factory is not policed (and two stores still re-emit
them post-open). **Fix:** widen the needles, bind the marker to test code, police durability
pragmas, and delete the duplicate store-side re-emissions.

### PR935-MEDIUM-003 — Bytecode gas ceiling bounds iterations, not wall-clock

`sens-api-gateway/src/scripting/bytecode_vm.rs` + `bytecode.rs` gas table. IO opcodes
(`LoadTag`/`WriteTag` = 5 gas, `FbCall` = 20 gas) cost µs-scale host work; a signed program at the
1M ceiling can legally occupy a worker for ~100–400 ms **every scan tick** — a deployable, permanent
drain of one of two workers. **Fix:** add a wall-clock deadline checked inside the VM dispatch loop
every N gas units (tier-1: the bound holds regardless of gas-weight calibration), terminating
through the existing budget-exhaustion path.

### PR935-MEDIUM-004 — Downlink queue eviction is priority- and confirmed-blind

`sens-api-gateway/src/lora/downlink_queue.rs`. Global overflow does an unconditional `pop_front()`
and the per-DevAddr cap rejects the newest unconditionally, while `DownlinkItem` carries `priority`
and `confirmed`. A telemetry-ack can evict another device's pending **confirmed actuator command**;
a fresh critical command is rejected in favour of stale queued items. **Fix:** evict the globally
worst item (lowest priority, unconfirmed-first, oldest-first) and admit the newcomer unless it is
itself the worst.

### PR935-MEDIUM-005 — Zombie OPC UA leases now lock operators out for the full 1-hour TTL

`sens-api-gateway/src/opc_ua_server/session_quota.rs` (`LEASE_FAIL_SAFE_TTL = 3600 s`). The lease_id
fix (a0441f53) is correct, but with no session-close callback the TTL is now the only release path:
a twice-crashed client blocks reconnection for up to an hour at `max_sessions_per_user = 2`.
**Fix:** derive the fail-safe TTL from the server's session lifetime SSoT instead of a magic
constant, so an abandoned session's slot frees shortly after the OPC UA session itself can no longer
be alive.

### PR935-MEDIUM-006 — io_poll holds the AppState read guard across the publish await

`sens-api-gateway/src/io_poll.rs` (`publish_io_data(&s, …)` under the `RwLock` read guard). tokio's
write-preferring `RwLock` queues **all** new readers behind a pending writer while io_poll sits in a
broker-timeout await — an agent-wide stall exactly during broker outages. The deferral in commit
f4c2afea carried no tracked finding. **Fix:** clone the publish handles out of the guard and drop it
before any await.

### PR935-MEDIUM-007 — GPIO fail-safe polarity is ambiguous under `invert`; I2C outputs have no safe-state

`sens-api-gateway/src/config.rs` (`safe_state_level` documented as physical), `src/gpio.rs` (actor
applies `invert` on every write), `src/safe_state.rs` (`from_config` collects Modbus + GPIO only).
On an `invert: true` pin the field drives the opposite physical level from its documentation — in a
life-safety field the physical contract must hold regardless of logical inversion. Separately,
`OutputTag::I2cOutput` is never collected, so I2C actuators receive no safe-state write at all
(pre-existing; the commit's closure claim overreached). **Fix:** make safe-state writes physical
(bypass `invert`) with an explicit test at `invert: true`; register the I2C gap as a tracked finding
with owner/deadline (PR935-MEDIUM-010 companion scope).

### PR935-MEDIUM-008 — Observability auth is per-handler opt-in, not fail-closed by construction

`sens-api-gateway/src/health.rs`. The gate is a hand-written `authorize()` call inside each
sensitive handler; the next route added to this router is anonymous by default. **Fix:** enforce as
router-level middleware with an explicit anonymous allowlist (`/health`, `/ready`); covers
PR935-HIGH-005 by construction.

### PR935-MEDIUM-009 — Registry/report state drift

`docs/reviews/_registry/findings.jsonl` vs
`docs/reviews/edge-expert/2026-07-11-sens-gateway-e2e-audit.md` and
`docs/plans/2026-06-18-enterprise-grade-debt-closure/finding-truth-table.md`. (a) 23 MEDIUM + 14 LOW
audit findings were never registered (the registry README declares itself the state store for
**every** finding); (b) the report re-scopes EDGE-CRITICAL-001 to OPEN while every machine surface
says RESOLVED — the re-open transition is missing; (c) the truth-table row for EDGE-CRITICAL-004
(`real-open`) was falsified by commit da33f906 in the same PR and never refreshed; (d) new registry
entries used placeholder midnight timestamps. **Fix:** backfill the 37 missing entries, append the
EDGE-CRITICAL-001 re-open transition, refresh the truth-table row, use real timestamps.

### PR935-MEDIUM-010 — SCADA process/package deploy accepts unsigned artifacts

`sens-api-gateway/src/commands/system.rs` (`DeploySigGate::Unsigned` accept-and-warn arms).
Bytecode/ST/program deploys **require** the cloud artifact signature; SCADA process/package deploys
accept unsigned payloads from any envelope-authorized operator, and the code carries banned deferral
language ("enforcement arrives with the Faz 5 bundle gate") with no tracked finding. Pre-existing
(0b8ad1ab only changed `verify`→`verify_strict` on the signed arm). This finding IS the tracked
owner/deadline record: **Owner:** edge-expert; **Deadline:** 2026-09-30 (lands with the Faz 5 bundle
gate or independently, whichever first). The unsigned-accept arm must become fail-closed in
Enforcing posture.

### PR935-MEDIUM-011 — MQTT `config` topic applies unauthenticated control-plane changes

`sens-api-gateway/src/commands/config_dispatch.rs` (`handle_config_update`). Telemetry-interval and
`scripting.enabled` changes apply with no signature, RBAC, or legacy-policy check — unaffected by
the new command-path gates, which cover the `commands` topic only. Pre-existing; recorded here so it
is not assumed covered. **Owner:** edge-expert; **Deadline:** 2026-09-30. Fix direction: route
`config` topic payloads through the same envelope verification + PolicyEngine authorization as
commands.
