## PLAT-HIGH-003 — Transport.NATS still binds nats v2 via JSONCodec; replace with a wire-compatible v3 transporter

### Problem (verified firsthand 2026-06-13)

`@nestjs/microservices@11.1.19` constructs its NATS serializers by calling
`require('nats').JSONCodec()` — confirmed at `serializers/nats-record.serializer.js:11`,
`deserializers/nats-response-json.deserializer.js:15`, and `client/client-nats.js:25`.
The `@nats-io/*` v3 split **removed `JSONCodec`**, so swapping the `nats` npm package
for the v3 packages crashes every `Transport.NATS` service at construction. This is
why PR-A had to retain nats v2. PR-B removes that dependency by replacing Nest's
built-in NATS transport with a platform-owned `CustomTransportStrategy` (server) and
`ClientProxy` (client), after which PR-C can delete nats v2 and ban it.

### Surface (firsthand-enumerated)

- **13 `ClientsModule.register` client sites:** admin-api-service ×6 (password-reset,
  billing, messaging-admin, modules, tenant, users), gateway-api/websocket,
  hr-service/scheduling, messaging-service ×5 (ai, app, gdpr, message, notification).
- **Server cutover:** `libs/backend-common/src/bootstrap/create-service-app.ts:665`.
- **ADR-015 anchor reused unchanged:** `nats-connection.factory.ts` `buildNatsConnectionOptions()` (client-agnostic).
- **Untouched:** `@MessagePattern` (10 files) + `@EventPattern` (2 files) handlers.

### Design — wire byte-compatibility is the safety property

Nest's `NatsRecordSerializer` emits `JSONCodec().encode({ ...packet, data })`, and
`JSONCodec` is byte-identical to `JSON.stringify` + UTF-8. The v3 transport reproduces
exactly these bytes, so a **rolling deploy of mixed v2/v3 services interoperates**
(a migrated v3 service answers an un-migrated v2 caller and vice-versa) with **zero
broker migration** — durable names, queue groups, and subject naming are preserved by
extending Nest's `Server`/`ClientProxy` base classes (which own `normalizePattern`).

The strategy/proxy are direct ports of Nest's own `ServerNats`/`ClientNats`, swapping
only the nats-v2 API for `@nats-io/{transport-node,nats-core}` and the JSONCodec
serializers for the v3 codec.

### Phase 1 (this commit) — verified wire codec

`nats-v3-codec.ts` + `__tests__/nats-v3-wire-compat.spec.ts`: the JSON serializers /
deserializers, proven **byte-identical** to nats v2 `JSONCodec` across the four
envelope shapes (string-pattern request, object-pattern request, event, response) —
16/16 assertions green locally. Static JSON fixtures pin the contract so it survives
PR-C's removal of nats v2; a live `JSONCodec` cross-check anchors the equivalence claim.
